## Exact Command Contract

The implementation must make the following repository-root commands exact and portable. They are the canonical command interface for this phase. No shell-specific wrapper may contain different verification logic. Lune entrypoints may orchestrate these commands, but their behavior and exit codes must remain identical on Linux and Windows.

| Purpose | Exact command | Success contract | Failure contract |
|---|---|---|---|
| Resolve managed tools | `rokit install` | Installs or resolves only the versions locked by the tracked Rokit manifest and exits zero. | Refuses an unknown source, version drift, untrusted artifact, checksum mismatch, or incomplete installation. |
| Verify tools and provenance | `lune run verify-tools` | Prints executable path, exact version, selected artifact identity, and verified integrity-record identity for all five tools, then exits zero. | Exits nonzero for a missing tool, shadowed executable, wrong version, missing provenance field, or checksum mismatch. |
| Format source | `stylua .` | Rewrites only configured Luau source, test, and Lune script inputs deterministically. | Exits nonzero and names unreadable or invalid input without changing unrelated files. |
| Check formatting | `stylua --check .` | Exits zero with no diff for all configured inputs. | Exits nonzero and identifies every nonconforming path. |
| Lint source | `selene .` | Applies the pinned Luau and Roblox standard-library contract to every configured Luau source set and exits zero. | Exits nonzero with path, line, rule, and diagnostic for every violation. |
| Run deterministic tests | `lune run test` | Runs repository, boundary, project-map, strict-source, source-map, artifact-normalization, and harness self-tests in deterministic order and exits zero. | Exits nonzero with stable test ID, expected result, actual result, and no false pass after a harness exception. |
| Generate source map | `rojo sourcemap default.project.json --output build/infinite-card-collector.sourcemap.json` | Produces a complete source map using repository-relative paths only. | Exits nonzero for invalid project mapping, missing input, duplicate target, or unwritable output. |
| Build project artifact | `rojo build default.project.json --output build/infinite-card-collector.rbxlx` | Produces the complete project model from tracked source and declared assets. | Exits nonzero for invalid mapping, missing source, unresolved declared asset, or partial output. |
| Serve Studio synchronization | `rojo serve default.project.json --address 127.0.0.1 --port 34872` | Starts the local-only Rojo server with no prompt and exposes the exact project mapping to the matching plugin. | Exits nonzero or a health check fails when the port, project, plugin protocol, or source mapping is unavailable. |
| Create release-candidate artifact packet | `lune run artifact` | Cleans generated output, generates the source map, builds twice in isolated output roots, proves byte equality, emits SHA-256 and SHA-512 files plus a normalized manifest, and exits zero. | Retains diagnostic output, exits nonzero, and does not label an artifact releasable when any build, equality, inventory, secret, or integrity check fails. |
| Validate documentation | `lune run docs` | Checks required command blocks, internal links, supported-platform claims, generated-file guidance, and protected-plan references. | Exits nonzero with stable documentation check IDs and affected paths. |
| Validate secret boundaries | `lune run secrets` | Scans tracked inputs and the candidate artifact inventory for forbidden credentials, private logs, raw profiles, local overrides, and machine paths. | Exits nonzero, redacts the finding in logs, and prevents artifact acceptance. |
| Run the full local and CI gate | `lune run ci` | Runs tool verification, format check, lint, tests, source-map validation, reproducible artifact creation, documentation validation, secret validation, and artifact inspection in that order. | Stops on the first unsafe prerequisite and returns a nonzero code while preserving bounded diagnostic evidence. |

The documented Rokit bootstrap commands for a workstation without Rokit must be platform-specific, checksum-first, and generated only after the exact release artifact and expected SHA-256 and SHA-512 values are recorded. Piping a remote download directly into a shell is prohibited. The bootstrap is complete only after `rokit --version` proves v1.2.0 and `rokit install` resolves the tracked manifest.

## Architecture and Implementation Boundaries

### Source and Dependency Direction

The Rojo project mapping must produce the master plan's logical instance tree from tracked local roots. The executor may choose concise local directory names while implementing task 004, but the choice becomes an explicit tracked contract in `default.project.json` and ordinary documentation. There must be one source of truth for each target instance. Duplicate mappings, implicit local overrides, and two physical files targeting the same Roblox instance are invalid.

The dependency direction is:

```text
tooling and tests inspect runtime source
client and server may depend on shared
gui is consumed by client presentation
server may depend on server-controlled assets by declared identity
shared depends on no client, server, service, DataStore, remote, or UI code
server depends on no client or StarterGui code
client depends on no ServerScriptService or ServerStorage code
runtime source never depends on tests, tooling, generated output, or local environment files
```

Every applicable Luau file begins in strict mode. The minimum bootstraps may prove initialization and emit bounded local diagnostic state, but they must not define a catalog, reward, profile, network action, collectible, score, purchase, trade, or other later-phase behavior. The server bootstrap remains the only authoritative runtime bootstrap. The client bootstrap remains presentation-only.

### Tool and Runtime Boundary

Rokit, Rojo, StyLua, Selene, and Lune are development and build tools. They are not Roblox runtime dependencies and must not be mapped into the project artifact. The release artifact must contain no tool executable, package cache, test harness, CI file, provenance report, secret scanner, local configuration, or build log.

No external gameplay runtime package is allowed in Phase 000. If a tool installation mechanism would implicitly add runtime modules or execute remote code beyond the reviewed artifacts, the phase stops until the mechanism is constrained or the plan is explicitly revised.

### Configuration, Secrets, and Permissions

Tracked configuration contains only safe defaults, stable identifiers, versions, repository-relative paths, loopback addresses, ports, and validation rules. Credentials, tokens, cookies, session material, Roblox account state, GitHub tokens, private logs, raw profiles, home-directory paths, and machine-specific Studio paths remain outside tracked files and artifacts.

The Rojo development server binds to `127.0.0.1:34872` by default. A nonloopback bind requires an explicit documented local override and a security review; it is not used in CI or phase acceptance. CI uses only the default repository token with least-privilege read access plus the minimum artifact and checks permissions required by the repository baseline. Phase 000 requires no Roblox publishing credential and no project secret.

### Test Harness and Determinism

Lune test discovery must be deterministic by stable test ID and normalized path. Fixtures use repository-relative paths, fixed inputs, and explicit output roots. Tests cannot depend on wall-clock time, locale, host username, home directory, network availability, unordered table traversal, random seed without capture, or prior cache state. A harness exception is a failed test run.

Artifact generation begins from a clean generated-output root. The source-input digest covers every tracked file that can affect the project output, including the project manifest and generated resource inputs, but excludes `.git`, caches, logs, local overrides, and prior outputs. The normalized artifact manifest contains no generation timestamp or absolute path. It records the source commit, tool versions, input digest, project-map digest, source-map digest, artifact SHA-256, artifact SHA-512, and instance inventory digest.

### Studio and Platform Support

Linux command-line development and CI are mandatory. Windows command-line portability and native Roblox Studio acceptance are mandatory. Because current evidence does not establish official native Linux Roblox Studio support, a Vinegar workflow is treated as conditional compatibility. If task 010 proves it, documentation names the exact Vinegar, Wine, Studio, and plugin versions and the support boundary. If it is unavailable or fails, documentation states that Linux supports the CLI workflow but requires a native supported Studio environment for authoritative acceptance.

The Studio plugin and Rojo CLI must consume the same `default.project.json`. Plugin synchronization must not require an untracked project file, manual copy into the place, or a different directory mapping. Parity compares the built instance inventory, source-map target paths, and synchronized Studio tree after a clean sync and after one controlled source update.

### CI Economy and Reproducibility

CI uses standard GitHub-hosted Linux and Windows runners only. It cancels superseded runs, applies explicit job timeouts, limits triggers and paths to meaningful changes, uses validated OS-specific caches keyed by the Rokit manifest and integrity-registry digest, and keeps routine artifacts only long enough for phase evidence and failure diagnosis. A cache hit never bypasses `verify-tools` or checksum validation. Studio acceptance remains a recorded manual runtime gate and is not falsely simulated in CI.

The Linux and Windows jobs run the same `lune run ci` interface. Platform-specific bootstrap logic may differ only for downloading and placing the verified Rokit executable; all repository verification behavior is shared through tracked cross-platform Luau entrypoints and direct pinned tool commands.
